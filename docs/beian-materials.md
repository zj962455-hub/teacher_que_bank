### 2.1 访问控制与身份认证

| 措施 | 实现方式 | 验证方式 |
|---|---|---|
| 身份认证 | 用户名 + 密码登录，口令用 **bcrypt 加盐哈希**存储 | `backend/app/services/auth.py` |
| 会话管理 | 服务端 Session 存数据库，客户端 token **只存 SHA-256 哈希**（库被拖走也拿不到可用凭证） | `backend/app/models.py` `Session_` |
| 强制下线 | 管理员改密码 / 注销会话后，对应 token 立即失效 | 个人中心 → 设备会话管理 |
| 账号停用 | `is_active=False` 软删除，保留业务数据但立即停用登录 | `backend/app/models.py` `User` |
| 账号发放 | 管理员预创建（`create_users.py`）；**另开手机号 + 短信验证码自助注册**（短信由阿里云下发，验证码 5 分钟有效、限频发送；注册通道可由管理员一键关闭） | `backend/app/scripts/create_users.py` · `app/routers/auth.py` `/api/auth/register` |
| 共享试用账号 | 多人共用同一账号时 `allow_password_change=false` —— 改密码会踢掉所有共用者的会话，所以**锁死改密**（后端 403，前端只是提示） | `app/models.py` `User.allow_password_change` |

### 2.2 数据隔离与访问授权

| 措施 | 实现方式 |
|---|---|
| 按用户隔离 | `questions` / `papers` / `uploads` 三张表的 `user_id` 均为 `NOT NULL` + 外键 + 索引 |

### 1. 页面显示什么

### 2. 三个容易踩的坑（都已踩过并修掉）

**① 链接的 `code` 参数只放数字，不能放中文全称**

```
✅ https://beian.mps.gov.cn/#/query/webSearch?code=33010602012345
❌ https://beian.mps.gov.cn/#/query/webSearch?code=浙公网安备XXXXXXXXXXXXXX号
```

依据：公安官网自己页面里硬编码的示例是纯数字（`?code=11010102000001`），
显示文字才是「京公网安备11010102000001号」。**显示用全称，链接用数字。**
代码里填一次全称即可，`MPS_CODE` 会自动摘出数字部分。

**② 公安徽章图标必须本地托管，不能外链**

官方老路径 `https://beian.mps.gov.cn/img/gh.png` **已失效**（2026-11-18 实测：
返回官网 SPA 的 index.html，`content-type: text/html`，749 字节 —— 浏览器会当
HTML 解析，页脚图标位置变空白/裂图）。

现做法：取官网真图（金色公安徽章 62×67 PNG）下载到 `frontend/public/gh-beian.png`
本地托管，链接仍指向官方查询页。对方改版也不会裂。

**③ 链接必须用 `:href` 绑定**

写成静态 `href="...{{ MPS }}"` 的话，Vue 的插值在属性里不生效 —— 会原样输出
成字面量 `?code={{ MPS }}`，**链接直接是废的**，而且因为号还没填、整块 `v-if`
不渲染，肉眼根本看不出来。

### 3. 拿到号之后的操作

1. 改 `frontend/src/components/SiteFooter.vue` 的 `MPS` 常量，填入公安备案号全称

   + 图标 naturalWidth > 0」）
5. 浏览器打开 `https://tqb.lanhu-lab.top/` 肉眼确认

## 八、安全评估的定性结论（2026-11-18 核对公安部官方办事指南）

### 8.1 平台口径

《安全评估办事指南》（公安部全国互联网安全管理服务平台官方发布）明确：

- 安全评估是**独立业务流**，不在网站备案表单里完成：
  【安全评估】→【发起安全评估】→ 选择「APP 或小程序下至少一个版本号，**或已填报完成的网站**」
- 申报材料：**自评估报告（必要，影印件加盖公章）** + 检测报告（非必要；若由第三方评估则必须上传）
- 审核：属地公安机关，**30 个自然日**；主体为单位按单位办公地址所属公安机关审核

《网站备案用户手册》5.2.1：新办网站申请共四步 —— 【开办主体】→【网站基本信息】→【网站负责人】→【提示说明】。
「开展评估情况」是最后一步的**声明项**，内容即《具有舆论属性或社会动员能力的互联网信息服务安全评估规定》
第十一条列出的五种触发情形。

### 8.2 蓝狐网的结论：五种情形均不适用

| 情形 | 是否触发 | 依据（线上实测，2026-11-18）|
|---|---|---|
| 1 具有舆论属性或社会动员能力的信息服务上线 | 否 | 无论坛/博客/微博/聊天室/通讯群组/公众账号/短视频/网络直播及相应功能（仓库实测：无 UGC 发布、无评论、无社区）；注册制封闭使用 |

### 9.1 用户真实身份核验及注册信息留存措施

**答法（可直接粘贴）**

本平台（网站名称「蓝狐网」，主域名 tqb.lanhu-lab.top）采用**手机号实名核验**方式注册，
注册成功后留存必要的注册与登录信息，并按规定期限保存、可追溯。

一、用户真实身份核验

1. 注册采用「手机号 + 短信验证码」核验：用户填写手机号后，系统通过阿里云短信认证服务
   （签名「恒创联众」）向该号码下发 6 位验证码，用户回填并核验通过后方可完成注册。
2. 验证码由短信服务商生成并保管，**本平台不生成、不存储验证码明文**，核验通过短信服务商的
   校验接口完成；验证码有效期 5 分钟，仅可使用一次。
3. 手机号本身由基础电信运营商实名登记，核验通过即证明注册人实际持有该真实可用的通信号码，
   是本平台认定的唯一身份标识。
4. 本平台**不采集、不存储身份证号**等身份证明信息，也未开展身份证实名核验。
   原因：平台为注册制、封闭使用的企业内部教学工具（教培数学教师题库），
   不面向公众提供信息发布与互动功能，无用户公开发布内容，
   无需将身份核验延伸至身份证层级；核验遵循最小必要原则，仅采集账号体系所必需的手机号。
5. 存量账号（管理员预创建后分发）首次登录强制修改初始密码（must_change_password 标记），
   密码统一以 bcrypt 加盐哈希存储，系统内不保留任何明文口令。
6. 账号可**单独停用**：停用后该账号立即无法登录，其已产生的业务数据保留可追溯，
   符合「可单独停用账号」的管理要求。

二、注册信息留存范围（最小必要）

1. 账号信息：手机号（登录名）、显示名（默认按手机号脱敏显示）、bcrypt 密码哈希、
   账号状态、是否管理员、是否允许自助改密、注册时间、最后登录时间。
2. 登录会话信息：会话令牌哈希、签发时间、最后使用时间、到期时间（会话有效期 7 天）、
   客户端 IP、User-Agent。会话令牌仅以哈希形式入库，明文只在客户端持有。
3. 短信核验流水：手机号、客户端 IP、动作（发送/核验）、用途（注册/找回密码）、
   核验结果、时间。**该表不记录验证码明文**，仅记录成功/失败结果，
   用于频控管控、安全审计与用户投诉溯源。
4. 不采集与业务无关的个人信息（不采集姓名、身份证号、精确位置、通讯录等）。

三、留存期限

1. 账号注册信息：长期留存，不做自动清理；账号停用采用软删除（置为停用状态），
   数据保留以保证业务数据可追溯、审计可回溯。
2. 短信核验流水：随业务数据库长期留存。
3. 登录会话：有效期 7 天，到期自动失效，失效会话无法继续使用。
4. 网络与访问日志：Web 访问日志按日轮转、保留 10 份；系统日志（journald）保留策略
   MaxRetentionSec=187904800 秒（约 5.95 年），覆盖注册、登录等关键操作留痕。
5. 数据备份：每日 04:17 对数据库与上传文件做全量备份，备份文件保留 14 天。

四、注册通道与风控

1. 自助注册通道具备独立开关，可在需要时随时关闭。
2. 验证码发送前在本地按维度限频，命中即拦截，不向短信服务商发起调用：
   同一号码最短间隔 60 秒；同一号码每日上限 10 条；同一 IP 每小时 20 条、每日 100 条；
   同一号码每小时验证码核验失败上限 10 次（防止对 6 位验证码穷举）。
3. 注册密码强度校验：长度不少于 8 位，且同时包含大写字母、小写字母与数字；
   不满足则拒绝注册。

### 9.2 对用户账号、操作时间、操作类型、网络源地址和目标地址、网络源端口、客户端硬件特征等日志信息，以及用户发布信息记录的留存措施

**答法（可直接粘贴）**

本平台建立了「应用层操作审计 + Web 访问日志 + 数据库留痕」三层日志体系，
对用户账号、操作时间、操作类型、网络源地址与目标地址、网络源端口、客户端软硬件特征等信息
逐条记录并按期限留存，可按账号、按时间窗、按来源 IP 检索与导出。

一、操作审计日志（audit_logs 表）

1. 记录内容：
   - 用户账号：用户 ID 与登录名（手机号）；
   - 操作时间：精确到毫秒；
   - 操作类型：HTTP 方法 + 接口路径 + 归一化操作名（如「题目管理」「账号注册」「密码重置」）；
   - 网络源地址：客户端公网 IP；网络源端口：客户端源端口；
   - 目标地址：目标域名（Host）+ 请求路径；
   - 客户端软硬件特征：User-Agent（含浏览器、操作系统、设备类型）；
   - 响应状态码与请求耗时。
2. 记录范围：平台全部 /api/ 接口调用，**包括未通过认证的访问尝试**（登录接口、注册接口、
   未授权访问均逐条记录）；未认证记录的用户账号为空，其余字段照常完整保留。
3. 与 Web 访问日志互补：Web 层（nginx access.log）记录源地址与源端口、目标域名、状态码、
   请求耗时；应用层额外补齐**登录账号**这一维度 —— Web 层只知道来源 IP，
   无法区分同一出口 IP 之后的不同用户。
4. 检索能力：审计表按「用户 + 时间」「时间」「源地址 + 时间」「操作类型 + 时间」四个维度建索引，
   支持按账号、按时间窗、按来源 IP 快速检索与导出。

二、留存期限

1. 操作审计日志（audit_logs 表）：**长期留存，不做自动清理**；账号停用采用软删除，
   数据与对应审计记录同步保留，保证可追溯。
2. Web 访问日志：按日轮转，保留 10 份（logrotate daily rotate 10）。
3. 系统日志（systemd journal，含应用异常堆栈与服务启停记录）：
   MaxRetentionSec=187904800 秒（约 5.95 年）。
4. 数据备份：每日 04:17 对数据库与上传文件做全量备份，备份文件保留 14 天。
5. 登录会话记录（sessions 表）：会话有效期 7 天，到期自动失效；会话令牌仅以哈希形式存储，
   同时留存签发时间、最后使用时间、来源 IP 与 User-Agent 供审计追溯。

三、用户发布信息记录的留存

1. 平台内用户发布的信息包括：题目（题干纯文本、Markdown、结构化内容块、图片路径）、
   试卷、上传的图片文件、分类与标签、用户反馈。每一条记录均关联**发布人账号**
   （user_id 外键指向 users）、**发布时间**与最后修改时间，可按人、按时间完整追溯。
2. 发布内容存储于业务数据库并纳入每日全量备份（备份保留 14 天），数据库数据本身长期留存；
   上传的图片文件随服务器文件系统保留并纳入备份。
3. 处置与追溯能力：题目与试卷支持单条删除与批量删除；账号可单独停用；
   用户反馈记录留存反馈内容、提交人、联系方式、来源页面与时间，并由管理员进行状态处置。
4. 平台不设面向公众的公开发布通道：唯一的免登录页面是试卷分享页，采用 32 字节随机 token
   （256 位熵）、强制过期、可随时吊销、仅授予单张试卷的只读查看；
   线上现有分享链接当前有效数为 0。

四、记录的可信性

1. 审计记录由服务端在请求处理完成后写入，不依赖客户端上报。
2. 后端服务仅监听 127.0.0.1，外部无法直连；来源地址与来源端口一律取自反向代理
   覆盖后的真实值（nginx 以 remote_addr / remote_port 覆盖客户端自带的同名头），
   客户端伪造的来源信息不予采信。

### 9.3 对用户账号和通讯群组名称、昵称、简介、备注、标识，信息发布、转发、评论和通讯群组等服务功能中违法有害信息的防范处置和有关记录保存措施

**答法（可直接粘贴）**

本平台针对用户账号标识信息与信息发布、转发等功能中的违法有害信息，建立了
「入口收窄 + 内容校验 + 可处置 + 留痕可查」四道措施。以下先说明平台的功能现状，
再逐项说明防范与处置措施。

一、服务功能现状（2026-11-18 全仓核查 + 线上实测）

1. 平台**不设通讯群组、聊天室、评论、跟帖、公开问答**等用户间互动功能。
2. 平台的「信息发布」形态为：用户在自己的私有空间内创建题目、试卷、分类、标签
   并上传图片；内容默认私有，访问需登录并校验归属（他人访问一律按「不存在」处理）。
3. 平台唯一的对外展示通道是「试卷分享链接」：分享页**只渲染试卷标题、题目标签与分值**，
   **不展示任何账号信息**（分享页模板中不含用户昵称、登录名、用户 ID）。
4. 分享链接的传播属性：32 字节随机 token（256 位熵）、强制过期（默认 7 天）、
   可随时吊销、仅授予单张试卷的只读查看、不可被搜索引擎索引；
   线上现有分享链接当前有效数为 0。

二、用户账号标识信息的管理与内容校验

1. 平台的用户标识字段仅有：**登录名（手机号，注册即唯一、不可修改）**与**显示名（昵称）**；
   **不设简介、通讯群组名称、备注、头像标识**等可自定义展示字段 ——
   从结构上收窄了可被写入违法有害信息的面。
2. 显示名在注册时填写、之后可自行修改，属于用户可写内容，已纳入内容校验（注册与修改资料
   两处均执行）：
   - 长度上限 50 字；
   - 不允许控制字符与零宽字符（防止藏匿内容）；
   - 不允许包含网址、域名与即时通讯账号（防止账号标识成为引流通道）；
   - 不允许包含违法违规内容（涉黄、赌博、毒品、恐怖暴力、诈骗黑产、违禁物品等类别的基础关键词）。
   - 校验不通过**直接拒绝并返回错误，不落库**。
3. 昵称不展示在任何公开页面，仅本人与管理员可见，且不参与检索、关注与互动，不具备传播属性。
4. 账号可由管理员**单独停用**，停用后该账号立即无法登录，其名下数据保留可追溯。

三、信息发布、转发环节的违法有害信息防范与处置

1. 上传环节：仅接受图片类型（PNG / JPEG / WEBP / GIF 白名单，**按 MIME 判定而不信任原文件名后缀**），
   单文件上限 5 MB，文件名加时间戳与随机后缀，文件与账号建立归属记录。
2. 处置能力（可对**内容本身**执行处置，而非仅下线入口）：
   - 上传的图片支持**删除**（上传者本人或管理员）：删除后文件从服务器磁盘移除，
     数据库归属记录同步删除；仍被题目引用时拒绝删除并提示先处理相关题目，避免误伤其他内容。
   - **删除题目时连带清理**其引用的图片文件（该文件未被其他题目引用时），
     确保处置后文件不残留于服务器磁盘。
   - 题目支持单条删除与批量删除；试卷支持删除。
   - 账号支持单独停用，停用后其全部登录令牌立即失效。
   - 试卷分享链接支持吊销，吊销后立即失效；已过期链接同样不可访问。
3. 内容巡查：管理员可通过题目列表、分享链接列表与操作审计日志巡检全站内容与操作，
   对发现的问题内容按上述链路处置并留痕。

四、违法有害信息的举报与受理渠道

   反馈内容与提交人、提交时间、来源页面一并留存。

五、有关记录的保存措施

1. 操作审计日志（audit_logs 表）记录全部接口操作，**包括内容删除、账号停用、分享链接吊销等
   处置动作本身**：记录操作人账号、操作时间、操作类型、源地址与源端口、目标地址、
   客户端特征、状态码与耗时，可按账号、按时间窗、按来源 IP 检索与导出。
2. 业务数据留痕：题目、试卷、上传文件、分类、标签、反馈等用户发布信息，
   均关联发布人账号、发布时间与最后修改时间，可按人、按时间完整追溯。
3. 处置痕迹留存：分享链接的吊销时间（revoked_at）与过期时间（expires_at）随记录保留；
   反馈的处置状态随记录保留；被删除内容在操作审计日志中留有删除操作记录。
4. 留存期限：操作审计日志长期留存；Web 访问日志按日轮转保留 10 份；
   系统日志约 5.95 年；数据备份每日一次、保留 14 天。

六、如实说明的局限

1. 上传图片**未接入自动违规图像识别**，处置依赖管理员巡查发现 + 人工执行删除链路；

2. 平台的防范能力建立在「无公开发布通道、无互动功能、内容默认私有」的结构性前提上，

### 9.4 个人信息保护，以及防范违法有害信息传播扩散、社会动员功能失控风险的技术措施

**答法（可直接粘贴）**

本平台按「告知公开 + 全程加密与最小授权 + 行为限流 + 内容可处置 + 留痕可追溯」的口径
落实个人信息保护；并针对违法有害信息传播扩散与社会动员功能失控风险，
采取「结构性收窄 + 对外通道受控 + 行为频控 + 快速处置 + 举报受理」的组合技术措施。

一、个人信息保护

1. **告知义务已履行**：站内设有公开的《隐私政策与用户协议》页面（网址 /privacy），
   以显著方式公开了处理者信息、处理目的与方式、信息种类、保存期限、
   行使查阅/更正/删除等权利的方式和程序，以及未成年人条款与 Cookie 说明；
   页脚设有该页面入口，未登录访客亦可直接访问。
2. **收集遵循最小必要**：仅收集账号体系所必需的手机号与显示名，
   不采集姓名、身份证号、精确位置、通讯录等与业务无关的个人信息；
   不使用第三方 Cookie、统计追踪与广告脚本。
3. **传输与存储安全**：全站 HTTPS 并启用 HSTS；口令以 bcrypt 加盐哈希存储，不可逆；
   数据库不对公网开放，仅服务器本机可访问；数据每日全量备份，备份文件权限受限。
4. **最小授权与数据隔离**：题目、试卷、上传文件、分类、标签均按归属校验，
   他人访问一律按「不存在」处理；接口文档关闭，敏感文件与路径穿越请求一律拒绝。
5. **防撞库**：登录失败按同账号（15 分钟内 5 次）与同 IP（15 分钟内涉及 10 个不同账号）
   两个维度限流，超阈值直接拒绝并返回 429；验证码发码按同号与同 IP 维度限频。
6. **删除权已落地**：个人中心提供「注销我的账号」（需输入密码确认），
   注销后账号停用、全部登录会话被撤销、全部分享链接被吊销、显示名被清除；
   账号发布的内容不再对外提供访问，物理删除可由运营方按用户请求在数据库层执行。
7. **留痕可追溯**：操作审计日志记录操作人账号、操作时间、操作类型、源地址与源端口、
   目标地址、客户端特征、状态码与耗时，可按账号、按时间窗、按来源 IP 检索与导出。

二、防范违法有害信息传播扩散、社会动员功能失控的技术措施

1. **结构性收窄（首要措施）**：平台不设通讯群组、聊天室、评论、跟帖、公开问答等
   用户间互动功能；内容默认私有，访问需登录并校验归属；
   分享页只渲染试卷标题、题目标签与分值，不展示任何账号信息。
   即从结构上不具备形成「内容聚合—二次扩散—群体动员」链路的前提。
2. **对外通道受控**：唯一的对外展示通道是试卷分享链接，采用 32 字节随机 token
   （256 位熵，不可枚举）、强制过期（默认 7 天）、可随时吊销、
   仅授予单张试卷的只读查看、不可被搜索引擎索引；
   平台不提供分享链接的公开列表或检索入口；线上现有分享链接当前有效数为 0。
3. **行为侧频控**：登录失败限流（同账号 15 分钟 5 次、同 IP 涉及 10 个不同账号）；
   验证码发码限频（同号最短间隔 60 秒、同号每日 10 条、同 IP 每小时 20 条、
   同 IP 每日 100 条、同号每小时核验失败 10 次），命中即拦截，不向短信服务商发起调用。
4. **内容侧校验与限制**：账号标识（显示名）内容校验，拦截违法违规内容与引流信息；
   上传仅接受图片类型白名单、单文件不超过 5 MB，文件名含随机后缀并与账号建立归属记录。
5. **快速处置能力**：上传图片可删除（文件从服务器磁盘移除）、删除题目连带清理其引用的图片文件、
   题目与试卷可删除、账号可单独停用（登录令牌全部失效）、
   分享链接可吊销（账号停用时自动吊销该账号全部分享链接）；
   全过程在操作审计日志留痕，可核查处置人、处置时间与处置对象。
6. **举报受理**：页脚公示违法和不良信息举报中心（12377）与公安网络违法犯罪举报网站；
   站内设「反馈」通道，由管理员集中受理并流转处理状态。
7. **应急预案**：违法有害信息处置流程已写入《公安联网备案材料》第四节，
   明确「发现—删除/吊销—停用账号—留痕—必要时上报」各环节与责任人。

三、如实说明的局限

1. 手机号以明文形式存储于业务数据库（作为登录名与审计记录的关联键），
   数据库不对公网开放、备份文件权限受限，但**未做字段级加密**；
   账号注销后手机号仍保留（属删除难以实现时的最小保留），物理清除需人工在数据库层执行。
2. 上传的试卷扫描件可能包含学生姓名、班级等个人信息，
   平台**未接入自动违规图像识别**，也未接入第三方内容审核服务，
   处置依赖管理员巡查发现 + 人工执行删除链路；
   使用者应事先取得学生及其监护人的必要授权，平台不提供授权凭证的留存机制。
3. 平台的防范能力建立在「无公开发布通道、无互动功能、内容默认私有」的结构性前提上；
   若后续开放公众注册、公开题库或用户间互动，需同步补充内容审核机制，
   并按评估要求重新申报。

### 9.5 为监管部门和执法部门依法履职提供技术、数据支持和协助的工作机制

> **答法（可直接粘贴）**
>
> 本平台已建立「制度明确 + 技术支撑 + 流程留痕 + 保密受控」的配合监管与执法工作机制，由管理员账号统一受理，专人专岗办理，全过程可追溯。
>
> **一、机制组成**
>
> 1. **制度与职责**：平台指定管理员为配合监管工作的对接责任人，负责接收监管部门、执法部门的数据调阅与协助请求，核验法律依据与文书编号，按本机制规定流程办理；其他人员无权导出、查阅或对外提供用户数据。
> 2. **技术支撑**：平台在后台提供**审计日志按条件导出能力**，支持按时间区间、操作账号、网络源地址、操作类型筛选，一键导出 CSV（带 BOM，Excel 直接打开中文不乱码），导出内容与安全评估要求的日志字段逐项对应：操作时间、操作账号、用户 ID、操作类型、请求方法与路径、网络源地址、**网络源端口**、目标地址与目标路径、响应状态码、耗时、客户端特征。
> 3. **配合方式**：可提供日志导出、数据核查、账号处置（停用/注销）、技术说明与现场协助等方式；提供的数据以最小必要为原则，仅覆盖请求文书载明的范围。
> 4. **留痕台账**：每次配合均登记台账，记录**请求单位、请求人、法律依据与文书编号、调阅范围、实际提供的数据内容、提供渠道、提供时间、提供人、对方回执编号**及备注，形成「一次配合、一条记录、双向留痕」。
> 5. **保密受控**：调阅数据仅限对接管理员在履职范围内使用，不得转作他用、不得留存于个人设备；导出文件按需删除并登记；涉及用户个人信息的部分在提供前做去标识化处理。
> 6. **全程可审计**：导出与登记动作本身同样进入平台操作审计日志，谁在何时导出了什么，可事后复核。
>
> **二、办理流程**
>
> 受理登记 → 依据核验 → 权限审批 → 数据准备与最小化 → 提供与登记 → 回执归档 → 事后复核
>
> - **受理登记**：登记请求单位、请求人、联系方式、法律依据及文书编号；
> - **依据核验**：核对文书真实性与所涉范围，超出授权范围的一律不提供；
> - **权限审批**：仅管理员账号可执行导出与登记，接口层强制鉴权（非管理员一律拒绝），操作同步写入审计日志；
> - **数据准备与最小化**：按请求范围筛选并导出，必要时去标识化；
> - **提供与登记**：通过平台导出、加密介质或书面方式提供，台账记录提供内容、方式、时间、提供人；
> - **回执归档**：取得对方回执或签收凭证的，编号一并登记归档；
> - **事后复核**：配合事项按季度复核台账，检查流程执行与保密要求落实情况。
>
> **三、已落地的技术措施（可核查）**
>
> | 措施 | 实现位置 | 说明 |
> |---|---|---|
> | 审计日志按条件导出 | `GET /api/compliance/audit/export`（仅管理员） | 支持时间区间、账号、IP、操作类型筛选，输出 CSV |
> | 导出行数上限 | 导出上限 50000 行 | 防止单次导出造成资源耗尽 |
> | CSV 公式注入防护 | 导出前单元格转义 | 以 `=` `+` `-` `@` 或控制字符开头的单元格统一加前缀转义，防止 Excel 打开时执行公式 |
> | 调阅台账 | `regulatory_requests` 表 + `/api/compliance/requests` | 记录请求单位、依据、范围、提供内容、时间、提供人、回执 |
> | 接口层权限隔离 | 管理员鉴权依赖 | 未登录返回 401，非管理员返回 403，前端隐藏入口不作为权限依据 |
> | 导出行为自身留痕 | 操作审计中间件 | 导出与登记动作同样入审计日志 |
> | 日志字段完整性 | 应用层审计 + nginx 扩展日志格式 | 源地址与源端口、目标地址、请求耗时等字段均已记录并实测验证 |
>
> **四、实测验证记录（2026-11-18）**
>
> 1. **权限验证**：普通账号调用导出与台账接口均返回 403（`auth.forbidden`）；管理员账号返回 200。
> 2. **登录态审计验证**：经公网 HTTPS 入口真实登录后发起请求，审计记录同一条内完整含 **操作账号、用户 ID、网络源地址、网络源端口、目标地址、目标路径、响应状态码**，例如 `账号登录 / POST /api/auth/login / 源地址 36.24.229.117 / 源端口 51823 / 目标 tqb.lanhu-lab.top / 状态码 200`。
> 3. **导出验证**：导出响应含 `Content-Disposition`（文件名）、`X-Export-Count`（本次条数）、`X-Export-Limit`（上限 50000）响应头，CSV 含 BOM 与完整表头。
> 4. **台账验证**：登记一条调阅记录后，台账列表可查回该条记录的全部字段。
> 5. **数据清理**：验证用测试账号、会话、审计行与台账测试条目均已删除，生产库无测试残留。
