## 二、网络安全技术措施

> 以下每一条都可在服务器上复现验证，附验证命令。

### 2.1 访问控制与身份认证

| 措施 | 实现方式 | 验证方式 |
|---|---|---|
| 身份认证 | 用户名 + 密码登录，口令用 **bcrypt 加盐哈希**存储 | `lesson-02/app/services/auth.py` |
| 会话管理 | 服务端 Session 存数据库，客户端 token **只存 SHA-256 哈希**（库被拖走也拿不到可用凭证） | `lesson-02/app/models.py` `Session_` |
| 强制下线 | 管理员改密码 / 注销会话后，对应 token 立即失效 | 个人中心 → 设备会话管理 |
| 账号停用 | `is_active=False` 软删除，保留业务数据但立即停用登录 | `lesson-02/app/models.py` `User` |
| 账号发放 | 管理员预创建（`create_users.py`）；灰度试用阶段**另开邀请码自助注册**（限次 / 限时 / 可停用） | `lesson-02/app/scripts/create_users.py` · `app/routers/auth.py` `/api/auth/register` |
| 共享试用账号 | 多人共用同一账号时 `allow_password_change=false` —— 改密码会踢掉所有共用者的会话，所以**锁死改密**（后端 403，前端只是提示） | `app/models.py` `User.allow_password_change` |

### 2.2 数据隔离与访问授权

| 措施 | 实现方式 |
|---|---|
| 按用户隔离 | `questions` / `papers` / `uploads` 三张表的 `user_id` 均为 `NOT NULL` + 外键 + 索引 |
| 越权防护 | 跨用户访问资源**统一返回 404**（不返回 403 —— 403 会泄露「资源存在」这一信息） |
| 上传文件归属 | 磁盘只保存随机文件名；原始文件名与 `user_id` 归属存 `uploads` 表；**上传和读取都校验登录态 + 归属** |
| 敏感文件拒绝 | nginx 拒绝 `/.env`、`/.git/*`、`*.sql`、`*.bak`、`*.conf`、`*.ini`、`*.log`、`*.sh`、`*.py` 及任意 `*.env` |
| 目录穿越防护 | 路径穿越请求返回 400，实测无任何文件内容泄露 |

### 2.3 网络与边界防护

| 措施 | 实现方式 | 实测结果 |
|---|---|---|
| 防火墙 | firewalld 启用，仅放行 `http` `https` `ssh` | 管理面板 cockpit 已移除 |
| 后端不暴露公网 | uvicorn 仅绑定 `127.0.0.1:8000`，公网只能经 nginx 80/443 进入 | `ss -tlnp` 确认 |
| 数据库不暴露公网 | PostgreSQL 仅监听 `127.0.0.1` | `DATABASE_URL` 指向 127.0.0.1 |
| 禁止目录列举 | 无 `autoindex on` | — |
| 隐藏服务器信息 | `server_tokens off`，不暴露 nginx 版本号 | `Server: nginx` |
| 备用入口说明 | `8.160.177.222` 直连保留 HTTP（运维排查用），域名访问强制 HTTPS | — |

### 2.4 传输加密

| 措施 | 实现方式 |
|---|---|
| HTTPS | Let's Encrypt 证书，`CN=tqb.lanhu-lab.top` |
| HTTP 强制跳转 | 域名访问 80 → 301 → 443；IP 直连保留 HTTP 通道 |
| HSTS | `Strict-Transport-Security: max-age=31536000; includeSubDomains` |
| 安全响应头 | `X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy: strict-origin-when-cross-origin`、`Permissions-Policy`（双层：nginx + 应用） |

### 2.5 信息泄露防护

| 措施 | 实现方式 | 实测 |
|---|---|---|
| 接口文档关闭 | 生产环境（`APP_ENV=production`）关闭 `/docs`、`/redoc`、`/openapi.json` | 三个均返回 404 |
| 错误信息不外泄 | 500 只返回「服务器内部错误」+ `request_id`；真实堆栈写入服务端日志 | — |
| 参数校验错误 | 422 只回字段名，不回显完整校验结构 | — |
| CORS | 生产环境跨域来源为空（同源部署，无需跨域） | — |
| 导出溯源 | 导出的 PDF **每页页脚**记录导出人、试卷名称、导出时间 | — |

### 2.6 日志留存与审计

| 措施 | 实现方式 | 实测 |

## 三、安全管理制度

| 制度 | 落实情况 |
|---|---|
| 账号管理制度 | 账号由管理员统一创建发放；灰度试用阶段开放**邀请码自助注册**（码限次、可设过期、可一键停用、名额用带条件的 UPDATE 原子占用）；用户可自行修改密码（个人中心） |
| 权限最小化 | 用户只能访问自己的题目/试卷/上传文件；无管理员后台批量查看他人数据的功能 |
| 变更管理 | 每次功能变更独立 Git commit 并推送，部署走统一脚本 `deploy/teacher-bank/rebuild.sh`（rsync → 权限 → 重启 → 验证） |
| 日志审计 | 服务端日志留存 6 个月，可追溯登录、查询、导出行为 |
| 应急预案 | 见下节 |
| 第三方组件管理 | 前端依赖锁定版本（package-lock.json）；后端依赖锁定在 venv |

## 四、应急处置流程

| 场景 | 处置动作 | 责任人 |
|---|---|---|
| 账号被盗用 | 个人中心 → 设备会话管理 → 注销该会话；管理员改密使旧 token 全部失效 | 负责人 |
| 用户数据泄露 | `is_active=False` 立即停用该账号 → 查日志定位范围 → 评估是否需向监管部门报告 | 负责人 |
| 服务异常 | `systemctl status teacherbank-api` 看状态 → `journalctl -u teacherbank-api -f` 看日志 → 回滚到上一 commit 重新部署 | 负责人 |
| 证书到期 | Let's Encrypt 自动续期；续期前会触发 nginx reload，需确认配置未丢 443 块（见 `docs/server-setup.md` 提醒） | 负责人 |
| 漏洞/攻击 | 临时用防火墙收紧端口 → 查 access_log → 修复后回归验证 | 负责人 |
