# 课 35 · OCR 识别率问题（灰度实测 2026-11-07）

> **结论**：错的根因不是「模型不够聪明」，而是 ①截图分辨率太低（短边只有 90~330 像素），
> 小符号（∠ ⊥ 分数）在这个尺度上检测不到；②mobile rec 把这些符号认成别的字
> （∠→Z、⊥→I/L、60°→6O°）。修法 = **先放大再识别 + 后端符号纠错 + 竖式分数重建**，
> 不需要换模型（换模型实测更差，见第四节）。

## 一、实测样本（老大 2026-11-07 15:37~15:44 上传的真实截图）

| 样本 | 尺寸 | 内容 | 修复前 mobile rec 输出 |
|---|---|---|---|
| A | 639×239 | △ABC 中 ∠B=∠C=60°，DE⊥AB，求 CE | `B=ZC=6O°`、`DEIAB` |
| B | 644×205 | 已知 OC 平分 ∠AOB，PD⊥OA，∠AOB=30° | `ZAOB`、`PDIOA` |
| C | 627×91 | ①∠A+∠B=∠C ②∠A:∠B:∠C=1:2:3 ③∠A=90°-∠B ④∠A=∠B=1/2∠C | `ZA+ZB=ZC`，分数整段丢失 |
| D | 650×326 | 等边△ABC，BQ⊥AD，求证 PQ=1/2BP（含三角形图） | `BQIAD`，分数散成两块 |
| E | 436×90 | 具备下列条件的△ABC中…（含三角形符号） | `A.A=B=3C`（∠ 整个消失） |

## 二、根因（已实测验证）

1. **分辨率太低**：这 5 张截图短边只有 90~326 像素，检测框在这个尺度根本找不到
   竖式分数和 ∠。放大 2 倍后，样本 C/D 的分数变成可识别的两个小块
   （分子 1、分母 2），样本 C 的分数分子也被找回。
2. **mobile rec 不认数学符号**：∠ 被读成 Z 或直接丢失，⊥ 被读成 I / L，
   `60°` 被读成 `6O°`。
3. **「公式块」其实是后端伪造的**：线上跑的是 paddleocr **2.7.3**，它
   **不支持** PP-StructureV3（SUPPORT_OCR_MODEL_VERSION 只有 PP-OCR~v4），
   而 `ocr.py` 的 `_iter_formulas` / `_iter_tables` 按 3.x 的
   `page["res"]["blocks"]` 结构取数据 —— 永远取不到。
   所以历史记录里那些 `type=formula` 块，全是后端 `enrich_blocks`
   把文本按数学字符切出来的伪公式（所以会出现 `A.A=B=3C` 这种）。

## 三、本轮落地的修复（已上线 + 已复测）

| 修复 | 位置 | 作用 |
|---|---|---|
| 小图放大 | `deploy/paddleocr/app/ocr.py`（`_preprocess`） | 短边 < `OCR_MIN_SIDE`（默认 350）时整体放大 `OCR_UPSCALE` 倍（默认 2）；长边 ≥ `OCR_MAX_LONG`（默认 2400）不放大；bbox 按倍数缩回原图坐标，前端高亮框不错位 |
| 检测框不缩回 | 同上（`det_limit_side_len=1920`） | 默认 960 会把放大后的图再缩回去，等于白放大 |
| 符号纠错 | `lesson-02/app/services/ocr_fixups.py`（`fix_math_symbols`） | ∠（Z/7/L 开头）、⊥（I/l/L/1）、60°（6O°）自动还原；只在「像数学文本」时生效，英文单词不受影响 |
| 竖式分数重建 | 同文件（`rebuild_fractions`） | 分子/分母两块靠 bbox 几何拼回 `\frac{1}{2}`；条件不满足宁可不拼 |
| 接入点 | `lesson-02/app/services/math_parser.py`（`enrich_blocks`） | 顺序：先纠错 → 再重建分数 → 再切 text/formula；**整块文本的 early return 也要带上修好的 text**（否则 `BQIAD` 修不回来） |
| 单测 | `lesson-02/tests/test_ocr_fixups.py`、`test_ocr_fixups_plain.py` | 15 条用例（符号 9 类 + 分数合并/不误合 + 整块文本 + 集成） |

### 复测结果（同一批 5 张样本，线上 OCR → 后端管线）

| 样本 | 修复前 | 修复后 |
|---|---|---|
| A | `B=ZC=6O°`、`DEIAB` | `\angle B=\angle C=60^\circ`、`DE⊥AB` ✅ |
| B | `ZAOB`、`PDIOA于D` | `∠AOB`、`PD⊥OA于D` ✅ |
| C | `ZA+ZB=ZC`，分数丢失 | `\angle A+\angle B=\angle C`，分数 → `\frac{1}{2}` ✅ |
| D | `BQIAD于点Q` | `BQ⊥AD于点Q` ✅（分数仍拆开，见下） |
| E | `A.A=B=3C` | 不变 ❌（模型把 ∠ 整个吞了，规则救不回） |

耗时：单张 0.7~2.2s（放大带来约 +0.5s）。

## 四、换模型：实测更差，不做

| 方案 | 实测结果 | 结论 |
|---|---|---|
| v4 **server** rec | ∠ 这类符号**直接吞掉**（`A+B=C`），比 mobile 更差；CPU 上慢 3~5 倍（2~6s/张） | ❌ |
| **PP-OCRv5 server** det+rec（paddleocr 3.x） | 单张 11~18s，峰值内存 3.2GB；这台机器总内存 3.5GB，跑到第 3 张直接被压到只剩 94MB | ❌ 硬件不够 |
| **PP-StructureV3**（paddleocr 3.x 全 pipeline） | 首次构造就下载 PP-DocBlockLayout + RT-DETR-L 表模型 + PP-FormulaNet_plus-L + PP-Chart2Table，进程 RSS 2.4GB，机器只剩 116MB，**已强杀**，不影响线上服务 | ❌ 内存卡线 |

结论：这台 2C4G 机器上，**PP-OCRv4 mobile + 放大 + 纠错** 是当前能达到的最优解。
真要上 PP-FormulaNet（直接输出 LaTeX），得先升机器（≥4G，最好 8G）或者加独立 OCR 节点。

## 五、还没解决的（需要老大配合 / 下一轮）

1. ~~**图形本身无法 OCR**~~ —— **本轮已解决（第七节）**：
   OCR 依然读不出三角形，但图不再丢：从原图里把几何示意图**裁出来单独存一份**
   （`questions.figure_path`），导出 PDF/JPG 时自动带上，编辑题目时也能看见。
   真正「让机器读懂图」仍然要更强模型或人工描述 —— 那是另一条路。
2. **上传分辨率**：老师现在截的图短边只有 90~330 像素。放大只能救回一部分；
   拍原题或用大图截图，识别率会明显更好。建议在上传处加提示。
3. **模型完全吞掉的符号**（样本 E 的 `A.A=B=3C`）：只能靠更强模型或老师手改。

## 七、图形保留：把图从像素里裁出来（2026-11-07 第二轮）

### 问题
OCR 只会输出文字，三角形、垂足、辅助线它一个也读不出来。
于是「文字全对、图没了」—— 学生的卷子上只剩一段没有图的证明题。
原先 `questions.image_path` 里存着原图，但导出 PDF/JPG 时压根没带上它。

### 为什么不能直接把原图塞进 PDF
原图 = 整张截图 = 文字 + 图。整张贴上去，学生的卷子上同一段话出现两遍。
所以必须**只把图那一块**摘出来。

### 怎么找到「图」那块
`lesson-02/app/services/figure_crop.py`（纯 Pillow，无新依赖）：

1. OCR 给了每个文本块的 bbox —— 那就是文字区
2. 文字区从图上抹掉（**只抹整行文字，不抹顶点字母的小方块** ——
   抹掉标注字母会正好压在几何线上，把线切断，实测样本 B 的底边就是这么断的）
3. 剩下的墨迹做连通块（游程 + 并查集），三条判据筛「线」：
   - 够长：长度 ≥ 1.8 倍字符高（单个汉字才 1 倍，直接出局）
   - 每行段数少：一行里最多 6 段墨迹 —— 一行汉字是 20+ 个独立字块，
     一张图是 1~5 条线穿过
   - 够空：墨迹面积 / 包围盒面积 ≤ 0.4（实心黑块、照片出局）
4. 挨得近的线聚成一簇，簇的宽高都要够（宽 ≥ 2 倍字符高、高 ≥ 1.5 倍字符高 ——
   一行文字的高度只有 1 倍字符高）
5. 裁出来存成独立 PNG，落 `uploads/`，写 `questions.figure_path`

阈值全是拿 5 张真实灰度样本反推的，不是拍脑袋：
`∠`/三角形交点处竖直厚度会飙到 22（用最大值会把整张图误判成「太粗」）、
样本 D 的图比样本 A 密（p75 厚度 12 vs 6）—— 所以最终改用
「每行段数」这个跟文字最像的判别信号。

### 落地的链路
- `questions.figure_path` 新字段 + 迁移 `009_add_figure_path.sql`
- `from-ocr` 入库时自动裁图（`_extract_figure`），裁不出来就留空，不影响入库
- 导出链路：`pdf_export.figure_file_url()` 把 `/api/uploads/x.png` 解析成
  **本地绝对路径的 `file://` URL**（PDF 渲染走 file:// 临时 HTML，不能回请求
  FastAPI，否则单 worker 死锁；`/api/uploads/` 还要 Authorization，Chromium 没有）
- 模板 `paper_pdf.html` 加 `.figure` 块（限高 62mm、不跨页切开）
- 前端 `QuestionEditor.vue` 加配图预览（带 token 取图）

## 八、踩坑：rsync 把本地权限带上线，nginx 直接 403

前端 `rsync -az --delete` 把本机 `dist/` 的 `0700` 和 UID 501 一并带到线上，
nginx（worker 身份 `nginx`）读不到 `/opt/teacher-bank/web/index.html` → **整站 403**。
现网前端是 root 跑的 rsync，用户写死在 `deploy/teacher-bank/rebuild.sh` 里。

**教训**：部署前端一律带 `--chown=nginx:nginx` + 事后 `chmod 755`，
不要指望 `rsync -a` 保留的权限刚好对。

## 九、本机强模型验证：2C4G 到底是不是瓶颈（2026-11-07 23:00）

### 结论先说
**是瓶颈。** 老大反馈的「符号识别还是不行」「分数不行」，不是规则能救的 ——
规则能救「∠ 被读成 Z」「⊥ 被读成 I」，但救不了「∠ 整个被吞掉」
和「分数的分子根本没认出来」。这是模型能力问题。

于是本机（M4/16GB）装了 PP-StructureV3（带 PP-FormulaNet_plus-L），
起了一个和线上**完全同契约**的本地 OCR 服务（端口 8099），
拿同一批 5 张灰度样本对拍。

### 对拍结果
| 样本 | 线上 PP-OCRv4 mobile + 规则纠错 | 本机 PP-StructureV3（真 LaTeX） |
|---|---|---|
| A | ∠B=∠C=60°（**规则还原**）、DE⊥AB（规则还原） | 模型直接给 \angle B=\angle C=60^{\circ} |
| B | PE//OA（∥→//） | PE/OA（∥→/，仍差一个符号） |
| C | ①ZA+ZB=ZC（**∠ 读成 Z**） | ①\angle A+\angle B=\angle C ✓ |
| D | PQ=-BP2（**分数拼不回**） | PQ={\frac{1}{2}}BP ✓ |
| E | A.A=B=3C（**∠ 整个吞掉**） | \angle A=\angle B=3\angle C ✓ |

强模型还多给一样东西：**图形区域被版面模型标成 image 块**（带 bbox），
三角形示意图的位置是模型直接给的 —— 比启发式裁图更准，
意味着接上强模型后 figure_crop 那套启发式可以退休。

### 代价（这才是线上没直接换的原因）
| | 本机 M4/16G | 线上 ECS 2C4G |
|---|---|---|
| PP-StructureV3 单张 | 18~21 秒 | **装不下**（RSS 2.4GB，机器只剩 116MB，已强杀） |
| 内存占用 | 3.46GB | — |
| PP-OCRv4 mobile 单张 | — | 2~4 秒 |
| PP-OCRv5 server det+rec | — | 11~18 秒、峰值 3.2GB（同样贴边） |

### 本机服务怎么用
见 deploy/local-ocr/README.md：./run_local_ocr.sh 起服务，
PADDLEOCR_BASE_URL 指到 http://127.0.0.1:8099 就能直接对比。

⚠️ 线上后端跑在 ECS 上，**它调不到老大 Mac 上的服务** ——
本地服务现阶段只能用于本地开发验证。要让线上用上强模型，三条路：
1. **升配**：ECS 升到 4C8G 以上，强模型能跑但单张 40~80 秒，交互偏慢
2. **隧道**：本机服务 + cloudflared/tailscale 暴露给 ECS，隐私也好，但依赖老师机器开机
3. **混合**：线上快模型先出结果（秒回），本机强模型异步校准后回写（推荐）
